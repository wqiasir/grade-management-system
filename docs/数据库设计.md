# 数据库设计 — 杭电计算机学院学生成绩管理系统

> 软件工程课程实践 · R12 交付文档
> 数据库：SQLite（开发 / 演示），ORM：SQLAlchemy 2.0 类型化写法，迁移：Alembic（Flask-Migrate）

---

## 1. 设计总览

6 张表，设计在 R1 冻结、全程未变。所有建表与变更都通过 Alembic 迁移，
测试里有"模型定义与迁移脚本无漂移"断言。

### ER 关系

```
user ──1:1── student ──1:N── enrollment ──N:1── course ──N:1── teacher ──1:1── user
                                   │
                                   └──1:N── score
```

- `user` 是账号中心，与 `student` / `teacher` 各为一对一（档案挂账号，删除档案连账号）；
- `enrollment`（选课）是学生与课程的多对多桥表，**成绩通过它落库**；
- `score` 挂在 `enrollment` 上而不是直接挂 `(student_id, course_id)`——
  从数据库层面杜绝"给未选课的学生打分"。

## 2. 表结构

### 2.1 `user` 账号表

| 字段 | 类型 | 约束 / 说明 |
| --- | --- | --- |
| id | INTEGER | 主键 |
| username | VARCHAR(64) | 唯一 + 索引；学生 = 学号、教师 = 工号、管理员自定 |
| password_hash | VARCHAR(256) | scrypt 哈希（`werkzeug.security`），**不存明文** |
| role | VARCHAR(16) | CHECK `ck_user_role`：`admin / teacher / student`；索引 |
| real_name | VARCHAR(64) | 非空 |
| is_active | BOOLEAN | 默认 True；停用即拦截登录并吊销在线会话 |
| created_at | DATETIME(tz) | 默认 `utcnow()`（带时区 UTC，规避 `datetime.utcnow` 陷阱） |

### 2.2 `student` 学生表

| 字段 | 类型 | 约束 / 说明 |
| --- | --- | --- |
| id | INTEGER | 主键 |
| user_id | INTEGER | → `user.id` **唯一**，`ondelete=CASCADE`（删账号连档案） |
| sno | VARCHAR(32) | 学号，唯一 + 索引 |
| name / gender / class_name | VARCHAR | gender 可空（男 / 女 / 未选择）；class_name 可空 |
| enroll_year | INTEGER | 入学年份，可空 |

### 2.3 `teacher` 教师表

| 字段 | 类型 | 约束 / 说明 |
| --- | --- | --- |
| id | INTEGER | 主键 |
| user_id | INTEGER | → `user.id` 唯一，级联 |
| tno | VARCHAR(32) | 工号，唯一 + 索引 |
| name / title / department | VARCHAR | title（职称）与 department 可空 |

### 2.4 `course` 课程表

| 字段 | 类型 | 约束 / 说明 |
| --- | --- | --- |
| id | INTEGER | 主键 |
| code | VARCHAR(32) | 课程代码，唯一 + 索引 |
| name | VARCHAR(128) | 非空 |
| credit / hours | FLOAT / INTEGER | 学分 0.5~20、学时 1~999（业务层校验） |
| teacher_id | INTEGER | → `teacher.id`，**可空**（"未排课"状态） |
| semester | VARCHAR(32) | 如 `2025-2026-1`（业务层正则校验），索引 |
| capacity | INTEGER | 默认 0；**`<= 0` 视为不限容量**（R6 口径） |

### 2.5 `enrollment` 选课表

| 字段 | 类型 | 约束 / 说明 |
| --- | --- | --- |
| id | INTEGER | 主键 |
| student_id | INTEGER | → `student.id`，级联，索引 |
| course_id | INTEGER | → `course.id`，级联，索引 |
| enrolled_at | DATETIME(tz) | 默认 `utcnow()` |

约束：**`UNIQUE(student_id, course_id)`**（`uq_enrollment_student_course`）——
重复选课的最后一道防线（视图层先查一次并给出友好提示，并发时捕获 `IntegrityError` 兜底）。

### 2.6 `score` 成绩表

| 字段 | 类型 | 约束 / 说明 |
| --- | --- | --- |
| id | INTEGER | 主键 |
| enrollment_id | INTEGER | → `enrollment.id`，级联，索引 |
| exam_type | VARCHAR(32) | 考核类型；应用层白名单 `平时 / 期中 / 期末`（`EXAM_TYPES`） |
| score | FLOAT | CHECK `ck_score_range`：`0 ≤ score ≤ 100`（数据库兜底） |
| updated_by | INTEGER | → `user.id`，可空；记录最后一次操作人（追溯） |
| updated_at | DATETIME(tz) | 默认 `utcnow()` + `onupdate` |

约束：**`UNIQUE(enrollment_id, exam_type)`**（`uq_score_enrollment_exam_type`）——
同一选课记录同一考核类型只有一条成绩；重复录入 = 更新（R7 / R10 均按此语义实现）。

> `exam_type` **有意不加数据库 CHECK**：R10 Excel 导入时列名即考核类型，
> 白名单校验收敛在应用层（`EXAM_TYPES`），数据库层留扩展余地。

## 3. 设计要点

1. **`enrollment` 不是冗余**：教师录成绩需要"这门课有哪些学生"，名单只能来自选课表；
   同时承载选课时间、容量控制（业务层 `_capacity_reached`）与"已出成绩不可退课"的判定。
2. **级联删除分三层**：删 `user` → 连档案（student / teacher）→ 连 enrollment → 连 score；
   课程删除连 enrollment / score；均由 ORM `cascade="all, delete-orphan"` +
   `ondelete=CASCADE` 双保险，测试逐层断言。
3. **业务层校验在数据库约束之前**：唯一约束给出的是 `IntegrityError`（用户看不懂），
   视图先查一次给出"不能重复选课 / 学号已存在"这类可操作提示；约束负责并发兜底。
4. **时间统一带时区 UTC**（`models.utcnow()`），避免 `datetime.utcnow` 的时区陷阱。

## 4. 迁移策略

- 模型变更 → `flask db migrate -m "R?:"` 生成脚本 → `flask db upgrade` 应用；
  **禁止手工改库**；`tests/test_app.py::test_migration_schema_matches_models` 防漂移；
- `flask init-db [--force]` 一条命令建库（内部走 Alembic upgrade）；
- 全程只有一份初始迁移（R1 建表），R6~R11 无结构变更——设计冻结的价值。

## 5. 数据规模与索引

| 场景 | 规模 | 支撑 |
| --- | --- | --- |
| 单机演示 | 学院规模（数百学生 / 每学期数十门课） | SQLite 单文件足够 |
| 列表页 | 每页 10 条分页 | `sno` / `tno` / `code` / `semester` 索引 + `username` 索引 |
| 统计 | 聚合在服务端一次分组查询完成 | `enrollment(course_id)` / `score(enrollment_id)` 索引 |
| 并发写入 | 单写者模型 | 唯一约束兜底重复；生产换 PostgreSQL/MySQL 并加事务锁 |
