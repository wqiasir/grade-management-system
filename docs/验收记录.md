## 第 1 轮验收 — 项目骨架与数据库

- **日期**：2026-09-22
- **本轮目标**：搭起可运行的 Flask 应用骨架，按冻结的数据模型建好 6 张表，并让 `pytest` 全绿。
- **实际交付**：
  - 应用工厂 `gradeapp/__init__.py`（`create_app()` + 首页 + `init-db` / `seed` 命令）
  - 扩展单例 `gradeapp/extensions.py`（`db` / `migrate` / `csrf`）
  - 6 张表 ORM 定义 `gradeapp/models.py`（`user`、`student`、`teacher`、`course`、`enrollment`、`score`）
  - Alembic 迁移目录 `migrations/`，初始迁移 `fba8e95c58f8_initial_schema_user_student_teacher_.py`
  - 首页模板 `gradeapp/templates/index.html` + 样式 `gradeapp/static/style.css`
  - 依赖冻结 `requirements.txt`、打包与工具配置 `pyproject.toml`、`.flaskenv`、`.gitignore`
  - 测试夹具 `tests/conftest.py`（`tempfile.mkstemp()` 临时库隔离）与 12 条测试 `tests/test_app.py`
  - git 仓库初始化，提交 `ff8c9ca`（`R1: 项目骨架与数据库`，16 个文件）
- **演示效果**（已实测的操作路径）：
  1. `flask init-db --force` → 走 Alembic 迁移建表，`flask db current` 显示 `fba8e95c58f8 (head)`；
     库中 7 张表 = 6 张业务表 + `alembic_version`。
  2. `flask seed` → 新增用户 3、学生 1、教师 1、课程 1；重复执行不产生重复数据。
  3. `flask run` → 访问 <http://127.0.0.1:5000/> 返回 `HTTP 200`，页面显示"**系统已启动**"，
     并列出 6 张表的建表状态与记录数（user 3 / student 1 / teacher 1 / course 1 / enrollment 0 / score 0）。
  4. 库中口令均为 `scrypt` 哈希（如 `scrypt:32768:8:1$...`），无明文。
- **测试结果**：`pytest` 通过 **12** 条 / 失败 **0** 条；
  `--cov=gradeapp` 覆盖率 **97%**（198 语句 / 漏 2，22 分支 / 部分 5）；
  分模块：`models.py` 100%、`extensions.py` 100%、`__init__.py` 95%。
- **遇到的问题**：
  1. **虚拟环境没有 pip**：`python -m venv` 建出的 `.venv` 只有 `python.exe`，没有 `pip` 与 `activate`
     脚本，`ensurepip` 与 `pip install` 均报 `PermissionError: [Errno 13]`（写不进 Python 自己创建的临时目录）。
  2. **迁移脚本弃用警告**：`flask db init` 生成的 `migrations/env.py` 调用 `db.get_engine()`，
     在 Flask-SQLAlchemy 3.1 下触发 `DeprecationWarning`（该接口将在 3.2 移除）。
  3. **Windows 下临时库删除失败风险**：测试夹具在 teardown 直接删 SQLite 文件时，
     连接池仍持有句柄会导致删除失败。
- **如何解决**：
  1. 在放宽文件权限的终端中删除 `.venv` 后重新创建并安装依赖，装到
     Flask 3.1.3 / Flask-SQLAlchemy 3.1.1 / Flask-Migrate 4.1.0 / Flask-WTF 1.3.0 / SQLAlchemy 2.0.54
     / pytest 8.4.2；随后 `pip freeze > requirements.txt` 冻结。运行测试/迁移时把 `TMP`/`TEMP`
     指向仓库内可写目录，规避沙箱对临时目录的限制。
  2. 把 `env.py` 的 `get_engine()` 改为优先使用 `db.engine`（保留旧版本分支），警告消除，测试输出干净。
  3. 夹具 teardown 顺序改为 `db.session.remove()` → `db.drop_all()` → `db.engine.dispose()` → 删文件，
     并对 `OSError` 容错。
- **遗留问题**：
  - 首页 `index.html` 目前是独立模板，R2 引入 `base.html` 后应重构为模板继承。
  - `exam_type` 未加数据库 CHECK 约束（有意保留灵活性，便于 R10 Excel 导入扩展考核类型）。
  - 学生/课程删除的级联策略只在数据库层做了 `ondelete="CASCADE"`，
    业务层规则（如"有成绩的学生能否删除"）留到 R4 / R5 决定。
  - 覆盖率虽已达 97%，但 R11 要求的是**权限矩阵与边界**覆盖，不能替代。
- **下轮计划**：R2 — 用户认证。`auth.py` 蓝图、`login.html`、`base.html` 骨架、
  `werkzeug.security` 口令校验、种子账号登录演示、`tests/test_auth.py`。
  （本轮 `User.set_password()` / `check_password()` 与种子账号已就绪，可直接使用。）

## 第 2 轮验收 — 用户认证

- **日期**：2026-09-23
- **本轮目标**：登录 / 登出 / 会话保持。三种角色账号均可登录，错误口令被拒并提示，登出后回到登录页。
- **实际交付**：
  - 认证蓝图 `gradeapp/auth.py`：`/auth/login`、`/auth/logout`、`LoginForm` / `LogoutForm`、
    `before_app_request` 加载当前用户、会话指纹（签发 / 校验 / 口令摘要）
  - `gradeapp/decorators.py`：`@login_required`（未登录跳登录页并带 `?next=`）
  - 模板 `templates/base.html`（导航 + 闪现消息 + footer 块，按角色渲染菜单）、
    `templates/auth/login.html`（登录表单 + 演示账号表）、`index.html` 重构为模板继承（挂上"当前登录状态"区块）
  - `static/style.css` 扩展：导航栏、卡片、表单、按钮、闪现消息、角色徽标
  - 应用工厂：注册认证蓝图；会话配置（`PERMANENT_SESSION_LIFETIME` 7 天、`HttpOnly`、`SameSite=Lax`）
  - 测试 `tests/test_auth.py` 35 条（登录页 / 三角色登录 / 失败路径 / 登出 / 会话保持与失效 / 开放重定向 / 口令哈希）
  - 端到端冒烟脚本 `docs/smoke_r2.py`（对真实服务发 HTTP 请求，33 项断言）
  - 文档：`README.md` 增补"认证与安全（R2）"章节、演示步骤与目录结构
- **演示效果**（已实测的操作路径）：
  1. `flask seed` 后，`admin`/`admin123`、`teacher`/`teacher123`、`student`/`student123` **三个账号均可登录**，
     登录后跳回首页，导航栏右上角显示姓名 + 角色徽标 + "退出登录"，首页"当前登录状态"显示用户名与角色中文名。
  2. 口令输错或用户名不存在 → 停在登录页，提示"**用户名或口令错误，请重新输入。**"
     （两种情况同一句提示，不泄露账号是否存在），且**不发放会话**；停用账号提示"该账号已被停用"。
  3. 点击"退出登录" → POST 到 `/auth/logout`（带 CSRF token）→ 会话清空 → 回登录页并提示"已安全退出登录。"；
     首页重新显示"未登录"。
  4. **会话保持**：登录后刷新页面、连续多次请求仍是同一用户；`session.permanent` 为真，cookie 有效期 7 天。
  5. 安全边界：`GET /auth/logout` → `405`；缺 CSRF token 的 POST → `400`；
     `?next=//evil.example.com` / `http://evil.com` / `javascript:` 一律回首页（只接受站内相对地址）。
  6. 管理员在后台改了某人口令（或停用账号）后，该用户**旧会话立即失效**，下一次请求即回到未登录状态。
  7. 额外用 `docs/smoke_r2.py`（标准库 urllib，不新增依赖）对**真实启动的 `flask run` 服务**跑了一遍
     端到端 HTTP 冒烟：未登录首页 → 错误口令 → 用户不存在 → 三个账号分别登录 / 会话保持 / 登出 → 安全边界，
     **33 项断言全部通过、0 项失败**（`python docs/smoke_r2.py http://127.0.0.1:5000`）。
- **测试结果**：`pytest` 通过 **47** 条 / 失败 **0** 条（R1 的 12 条 + R2 的 35 条）；
  `--cov=gradeapp` 覆盖率 **98%**（314 语句 / 漏 2，38 分支 / 部分 5）；
  分模块：`auth.py` 100%、`decorators.py` 100%、`models.py` 100%、`extensions.py` 100%、`__init__.py` 95%。
- **遇到的问题**：
  1. **首页测试被新增内容影响**：把首页改成模板继承后，`test_app.py` 里原有的断言（"系统已启动"、6 张表名、
     版本号）必须继续成立，改动模板时容易漏。
  2. **登出按钮的 CSRF token**：校验 CSRF 的表单必须有 token，但登出按钮在 `base.html` 的导航里，
     每个页面（含未登录页面）都要能渲染它。
  3. **沙箱下 `tmp_path` 不可用**：为验证"CSRF 真的会拦截"新写的测试用了 pytest 的 `tmp_path` 夹具，
     在当前受限环境下 `PermissionError: [WinError 5]`（无法在 `.tmp` 下创建目录）。
- **如何解决**：
  1. 保持首页既有内容不变，只**追加**登录状态区块；模板继承后重跑 `test_app.py`，原有断言全部保持通过。
  2. 用 `bp.app_context_processor` 注入一个空的 `LogoutForm()` 实例，在 `base.html` 里用
     `{{ logout_form.hidden_tag() }}` 输出 token——表单依然由 Flask-WTF 生成，不绕过 CSRF。
  3. 改用与 `conftest.py` 一致的 `tempfile.mkstemp()` 生成临时 SQLite 文件，并在 `finally` 里
     `session.remove()` → `drop_all()` → `engine.dispose()` → 删文件，测试恢复全绿。
- **遗留问题**：
  - 权限控制目前只有 `@login_required`；**按角色的 `@role_required` 与 403 页面留到 R3**
    （第 6 节的权限矩阵要求行级校验，R3 起在每个视图内落实）。
  - 导航里"学生管理 / 我的成绩 / 选课"等菜单项是灰色占位，R3~R8 逐轮启用。
  - 会话有效期暂定 7 天，暂未做"记住我"开关与登录失败次数限制（如验收追问，可作为加固项）。
- **下轮计划**：R3 — 角色权限控制（RBAC）。在 `decorators.py` 补 `@role_required(*roles)`、
  新增 `templates/errors/403.html`、导航与首页按角色区分、`tests/test_permissions.py` 覆盖权限矩阵。
