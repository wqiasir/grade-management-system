# 需求分析 — 杭电计算机学院学生成绩管理系统

> 软件工程课程实践 · R12 交付文档
> 使用单位：杭州电子科技大学计算机学院（简称"杭电计算机学院"）
> 系统：B/S 架构 Web 应用，Python 3.12 + Flask + SQLite

---

## 1. 项目背景与目标

计算机学院需要一个面向教学场景的学生成绩管理系统，替代"Excel 文件 + 微信传文件"的手工流程。
系统以**本学院**为数据范围，覆盖学生、教师、课程三份基础档案的管理，选课、
成绩录入与查询、统计报表、Excel 导入导出等核心业务。

**核心目标**：

1. 三种角色（管理员 / 教师 / 学生）各得其所，数据范围按角色严格收缩；
2. 每一轮迭代结束时系统"可运行、可演示、测试全绿"（12 轮迭代交付）；
3. 安全底线明确：口令只存哈希、服务端鉴权、CSRF 防护、不开放自主注册。

## 2. 用户角色与使用场景

| 角色 | 典型场景 | 数据范围 |
| --- | --- | --- |
| 管理员 | 开学建档案（学生 / 教师 / 课程）、处理账号问题、查看全校统计 | 全校 |
| 教师 | 学期中录成绩（平时 / 期中 / 期末）、导出成绩表、查看自己课程的统计 | 仅自己授课的课程 |
| 学生 | 选课 / 退课、查自己的成绩单、导出本人成绩单 | 仅本人 |

账号由管理员创建（**不开放自主注册**）：新建学生 / 教师档案时自动建立登录账号，
用户名 = 学号 / 工号，初始密码默认 `123456`（创建后闪现提示，可自定义）。

## 3. 功能需求

功能按 12 轮迭代交付，每轮一个功能（R1~R5 为地基与档案，R6~R8 为核心业务，
R9~R10 为增值功能，R11~R12 为质量与交付）。

| 编号 | 需求 | 交付轮次 | 说明 |
| --- | --- | --- | --- |
| FR-01 | 系统骨架与数据库 | R1 | 6 张表，Alembic 迁移管理建表 |
| FR-02 | 登录 / 登出 / 会话保持 | R2 | 口令哈希、会话指纹、7 天有效期 |
| FR-03 | 角色权限控制（RBAC） | R3 | `@role_required` + 403 页面 + 行级校验 |
| FR-04 | 账号管理 | R3 | 列表 / 筛选 / 搜索 / 分页 / 停用启用 |
| FR-05 | 学生信息管理 | R4 | 网页增删改查，自动建账号 |
| FR-06 | 教师管理 | R5 | 网页增删改查；**仍授课禁止删除** |
| FR-07 | 课程管理 | R5 | 网页增删改查；容量 ≥ 已选人数 |
| FR-08 | 选课 / 退课 | R6 | 学生自助、管理员代选；容量上限；重复与已满拦截 |
| FR-09 | 成绩录入 | R7 | 按考核类型（平时 / 期中 / 期末）批量录入 / 修改；0~100 校验 |
| FR-10 | 成绩查询 | R8 | 学生本人成绩单（按学期分组）；管理员查任意学生 |
| FR-11 | 统计报表 | R9 | 汇总 / 分数段分布 / 课程平均分 / 班级排名（Chart.js） |
| FR-12 | Excel 导入导出 | R10 | 课程成绩表与本人成绩单导出；导出即模板、导入部分保存 |
| FR-13 | 测试体系 | R11 | 242 条测试全绿，覆盖率 98%，路由清单双向校验 |
| FR-14 | 部署与交付 | R12 | 密钥环境化、waitress 生产启动、三份交付文档 |

### 3.1 关键业务规则

1. **权限是服务端的职责**：导航"看不见"不算控制；每条受限路由 × 三种角色 × 未登录
   逐格断言（权限矩阵）；"是不是自己教的课"必须在视图内做行级校验（`guard_course_access`）。
2. **成绩挂在选课上**：`score` 通过 `enrollment` 关联学生与课程，数据库层面杜绝
   "给未选课的学生打分"。
3. **已出成绩不可退课**：选课记录下存在任意成绩，学生 / 管理员都不能移除该记录。
4. **同一考核类型唯一**：`(enrollment_id, exam_type)` 唯一约束——重复录入 = 更新。
5. **删除策略**：删学生 / 课程级联删选课与成绩（二次确认）；仍授课的教师禁止删除。
6. **部分保存**：成绩录入（网页与 Excel 导入同策略）遇到无效行逐条报告，
   有效行照常保存；留空 = 不修改。

## 4. 非功能需求

| 类别 | 要求 | 实现 |
| --- | --- | --- |
| 安全 | 口令不明文 | scrypt 哈希（werkzeug），库中无明文 |
| 安全 | 防 CSRF | Flask-WTF 全局 CSRFProtect；登出仅接受 POST |
| 安全 | 防开放重定向 | `?next=` 仅接受站内相对地址 |
| 安全 | 会话不可被篡改 / 吊销 | 会话指纹签名；改密 / 停用立即失效 |
| 可用性 | 每轮可演示 | 每轮结束 `pytest` 全绿，不留半成品跨轮 |
| 可维护性 | 结构变更可追溯 | 全部走 Alembic 迁移，模型与迁移一致性有测试 |
| 可维护性 | 测试回归防护 | 242 条测试 + 路由清单双向校验（新增路由漏测即红） |
| 部署 | 密钥不进仓库 | `SECRET_KEY` 从环境变量 / `.env` 注入；未配置自动生成随机密钥并告警 |
| 部署 | 生产服务器 | waitress（纯 Python，Windows 友好），`python serve.py` 一键启动 |
| 性能 | 单机演示规模 | SQLite 单写者够用；列表分页（每页 10 条）；统计聚合在服务端 |

## 5. 用例示例（成绩流转主线）

1. 管理员建学生 / 教师 / 课程档案（R4 / R5）；
2. 学生登录选课，容量满 / 重复选被拒（R6）；
3. 教师在自己课程的详情页录入平时成绩，再切到期中、期末（R7）；
4. 学生在「我的成绩」看到按学期分组的成绩单（R8）；
5. 管理员在统计报表看全校分数段分布与班级排名（R9）；
6. 教师导出成绩表填完再导入更新（R10）。

## 6. 范围外（明确不做）

- 跨学院数据、自主注册、成绩修改的完整审计链（只留最后操作人 / 时间）；
- 并发写冲突的数据库级锁（SQLite 单写者模型下以唯一约束兜底，生产换 PostgreSQL/MySQL）；
- 移动端专门界面（页面自适应但不做 App）。
